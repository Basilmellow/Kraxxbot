# Kraxx AI V1

Kraxx AI answers only explicit `@KraxxBot question` mentions and `/ask question` commands. It does not listen to unrelated messages, read channel history, search the web, or take actions. The gateway uses the non-privileged `GuildMessages` intent and does not request `MessageContent`; Discord makes content available for messages that specifically mention the bot. See Discord's [Message Content Intent alternatives](https://support-dev.discord.com/hc/en-us/articles/6383579033751-Message-Content-Intent-Alternatives-Workarounds).

The bot worker uses Google's official `@google/genai` SDK with `gemini-3.8-flash`, which Google's current model documentation identifies as stable and whose Standard tier currently lists free input/output tokens. Availability depends on project/model access, quotas, and rate limits. Free usage is not unlimited and eligibility can change. Review [model availability](https://ai.google.dev/gemini-api/docs/models), [pricing](https://ai.google.dev/gemini-api/docs/pricing), and [rate limits](https://ai.google.dev/gemini-api/docs/rate-limits) before launch. The provider is server-side only and uses `GEMINI_API_KEY` from the bot worker's local ignored `.env` or deployment secret manager. `.env.example` contains only an empty placeholder; never put the key in dashboard environment, database, Discord, source, or logs.

Guild configuration is stored in the existing `GuildModule` row for `kraxx-ai`; this module is disabled by default. Empty allowed-channel selection means all guild text/announcement channels. Defaults are a 10-second per-user cooldown, 10 requests per guild per minute, 1,200-character input and output caps, and a 12-second provider deadline. The application enforces its own bounded limits regardless of Google's quotas.

Operational telemetry stores guild/user/channel/request IDs, provider/model, status, latency, token counts when returned, and safe error codes. Prompt and response text are not persisted or logged. No telemetry retention/expiry job is implemented in V1; records remain until the related guild is deleted or records are otherwise removed under the database's applicable retention process. Explicit prompt text is transmitted to Google for model generation. Google's pricing page indicates data-handling differences between tiers; server administrators should review Google's current provider terms/privacy and choose an appropriate tier before enabling the module.

AI responses are sent only through the existing `MessageOperationService`, with mention parsing disabled. Provider timeouts/server/network failures are recorded as `PROVIDER_UNKNOWN` because the remote request may have completed; a repeated Discord interaction does not submit another provider request. Delivery ambiguity is separately tracked by `MessageOperationService`. Provider output is response-only: no tools, code execution, search grounding, function calling, Discord actions, or arbitrary system prompts are enabled.
